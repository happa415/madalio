# Madalio v1.5.1

日付付きのメモをブラウザ内に保存できる、シンプルなWebアプリです。

Madalioという名前は、タガログ語で「簡単」を意味する「Madali」から着想を得ています。

## 主な機能

- 内容を入力し、当日の日付で記録を保存
- 日付が新しい順に記録を表示
- 記録内容のコピー
- 保存済み記録の編集・削除
- 作成日時と最終編集日時の表示
- `localStorage`への自動保存
- JSON形式でのバックアップ・追加／更新読み込み
- スマートフォン表示への対応

## 使い方

### 起動

メモ機能に外部ライブラリやビルド作業は必要ありません。アクセス解析用スクリプトは外部から読み込みますが、取得できなくてもメモ機能は利用できます。`index.html`をブラウザで開くと利用できます。

ブラウザの制限により一部の機能が動作しない場合は、このディレクトリでローカルWebサーバーを起動してください。例えばPythonがインストールされている環境では、次のコマンドを使用できます。

```sh
python3 -m http.server 8000
```

起動後、ブラウザで `http://localhost:8000` を開きます。

### 記録する

1. 内容を入力します。
2. 「保存する」を押します。日付は自動で当日の日付になります。

記録一覧では、各記録に次の操作ボタンが表示されます。

- 「コピー」：記録内容をクリップボードにコピーします。
- 「編集」：内容を編集します。日付と作成日時は変わりません。
- 「削除」：確認後に記録を削除します。

## バックアップ

### 書き出し

「保存」で全メモをUTF-8のJSONファイルに保存します。メモが0件でも書き出せます。
ファイル名は `madalio-backup-YYYY-MM-DD.json` です。

ルートには `app: "Madalio"`、`formatVersion: 1`、メモ配列 `records` を含みます。
各メモの `id`、`date`、`text`、`createdAt`、`updatedAt` を保持します。

### 読み込み

- 「開く」からJSONバックアップを選択します。CSVには対応していません。
- 形式・バージョン・必須フィールド・データ型・日付・ID重複を検証します。
- `date` は実在する `YYYY-MM-DD`、日時はタイムゾーン付きISO 8601形式（例：`2026-10-25T01:23:45.678Z`、`2026-10-25T10:23:45+09:00`、小数秒は省略または1〜3桁）です。未編集の `updatedAt` は `null` です。
- 追加・更新がある場合に1回確認します。未保存入力がなければ「JSONバックアップを読み込みますか？」に続けて、バックアップのメモを追加・更新する旨を表示します。未保存入力があれば、読み込み成功後にその入力が破棄されることを明示します。新規入力の空白・改行、編集中の本文の削除も未保存変更として扱います。
- IDを基準に、新しいメモを追加します。JSONにない既存メモは保持します。
- 同じIDのメモは、全フィールドが一致すれば変更しません。異なる場合は `updatedAt`（`null` なら `createdAt`）を時刻として比較し、新しい方を採用します。同時刻なら現在のメモを優先します。
- 完了後に、JSON内のメモについて追加件数・更新件数・変更なし件数を表示します。古い日時または同時刻で採用されなかったメモも「変更なし」に含みます。
- ID・日付・本文・作成日時・編集日時をそのまま復元し、再生成しません。
- 空配列（`records: []`）では既存メモを削除しません。
- キャンセル、検証失敗、保存失敗の場合、現在のメモと編集中の内容は変更されません。
- 承認後に統合結果をlocalStorageへ一括保存し、成功した後だけ入力を消去して編集を終了します。変更がない場合は確認・保存・一覧更新を行わず、入力と編集状態を保持します。確認中に入力やメモが変わった場合は読み込みを中止します。

復元前には、必要に応じて現在のメモもJSONでバックアップしてください。

## データの保存について

記録は、利用中のブラウザの`localStorage`に保存されます。記録データのサーバーへの送信や、別のブラウザ・端末との自動同期は行いません。アクセス解析のための外部通信については下記を参照してください。

旧形式のメモで `updatedAt` が存在しない場合、通常起動時にメモリ上だけで `null` を補完します。起動時にlocalStorageへ書き戻しません。他の項目は保持し、明示された不正な値は引き続き拒否します。通常操作の保存成功時には補完値も保存されます。JSON読み込みは従来の厳格な検証を維持します。

作成・編集・削除とJSON読み込みは、localStorageへの保存成功後に一覧へ反映します。保存に失敗した場合は元のメモと入力中の本文を保持し、エラーを表示します。

保存キーが存在しない初回起動は、正常な空の一覧として開始します。一方、保存データを読み込めない場合や、形式・必須項目・日時・ID重複などに異常がある場合は、エラーを表示し、作成・編集・削除・JSON読み込み／書き出しを停止します。元データの自動削除・初期化は行いません。読み込み可能な状態に戻った後、ページを再読み込みすると通常利用に戻ります。

次の操作によって記録が失われる可能性があります。

- ブラウザのWebサイトデータや閲覧データを削除する
- プライベートブラウズなど、データを永続保存しないモードを利用する
- 別のブラウザ、端末、ホスト名またはポート番号からアプリを開く

大切な記録は、定期的にJSONでバックアップしてください。

## オフライン起動（PWA 第1段階）

Service WorkerがHTML・CSS・JavaScript・Manifest・アイコンをCache Storageへ版ごとに保存します。初回はオンラインでのアクセスと、必須ファイルすべてのキャッシュ・Worker有効化が必要です。登録だけでは準備完了ではありません。準備後はオフラインでも一覧・作成・編集・削除・コピー・JSON入出力を利用できます。JSONファイルは端末内に取得済みのものを使ってください。

メモは従来どおりlocalStorage、アプリ本体はCache Storageに保存します。WorkerはlocalStorageやJSONバックアップを操作しません。キャッシュ削除とメモ削除は別です。ただし、ブラウザの「サイトデータをすべて削除」はメモも消す可能性があります。定期的にJSONでバックアップしてください。

`madalio-icon-source.png` を元に、PWA用192・512px、Apple Touch Icon用180px、favicon用32pxのPNGを `icons/` に配置しています。元画像の白い外周余白を切り取り、外周に連続する白を透明化して正方形・配色を維持し、Manifestでは通常アイコン（`purpose: any`）として使用します。

### 登録条件とLive Serverでのテスト

- 本番は `https://happa415.github.io/madalio/` 内で登録します。
- localhost・127.0.0.1・IPv6ループバックでは `?pwa-test=1` を付けた場合だけ登録します。例：`http://localhost:5500/?pwa-test=1`。
- 通常のローカル開発では指定を外してください。残っている同ディレクトリのMadalio Workerを登録解除し、制御が残る間も通常開発のページと資産はネットワークから読みます。切り替え時は同じアプリのテスト用タブも閉じてください。
- 開発ではホストとポートを固定してください。GitHub Pagesとは保存領域が異なります。LANのHTTPアドレスや `file://` ではPWA試験はできません。
- Live Serverの自動リロードは、更新・未保存本文保持の試験中は停止してください。

Chrome DevToolsのApplicationでService Workersの状態がactivatedになり、Cache Storageに必須9URL（トップ・index.html・版付きCSS・版付きJS・Manifest・4種類のアイコン）がそろったことを確認します。もう一度PWAテストURLを開いて制御を受け、Offlineを有効にして通常再読み込みします。トップと `index.html?pwa-test=1` の両方、ブラウザを閉じた後の再起動、各メモ操作とJSON入出力を確認してください。本番ではテストクエリは不要です。

### 更新とバージョン管理

1. `index.html` のCSS・JS参照の `?v=` と表示バージョン、`script.js` の `APP_VERSION`、`sw.js` の `VERSION`、READMEの版を同じ新しい値へ更新します。HTML・CSS・JS・Manifest・Workerの変更時は毎回、未使用の版番号を使います。
2. 必須ファイルを同じリリースとしてまとめて公開します。`sw.js` のファイル名は変えません。今回の作業では公開していません。
3. 新版は別キャッシュへ全資産を保存した後に待機します。取得や版検証に失敗した場合は新版を破棄し、旧版を維持します。次のオンラインアクセスで再試行します。
4. 全Madalioタブ・アプリ画面を閉じ、次回起動で新版を使います。単なる再読み込みだけでは新版へ切り替わらない場合があります。編集中の強制リロードはしません。
5. 新版有効化時は、同ディレクトリのMadalio専用旧キャッシュだけを削除します。localStorageは維持します。

### 開発用Workerとキャッシュの解除

先に必要なメモをJSONで保存します。PWAテスト用タブを閉じ、テスト指定なしのURLを開きます。Chrome DevToolsのApplication → Service Workersで、その開発URLの `sw.js` をUnregisterします。Cache Storageでは `madalio-（パス）-assets-` で始まる該当アプリのキャッシュだけを削除します。全タブを閉じて開き直してください。Local Storageや「Clear site data」は削除しません。Firefoxも開発者ツールのApplication／Storageから登録と該当キャッシュを確認できます。

### Safari・ホーム画面アプリへの移行

Safari通常タブとホーム画面アプリは保存領域が異なる場合があり、メモの自動引き継ぎは前提にしません。元のSafariでJSONを書き出し、ホーム画面アプリをオンラインで初回起動してから、そのJSONを読み込みます。件数・内容を確認するまで元データとJSONを残してください。読み込みは現行のID・更新日時による追加更新方式です。削除の同期は行いません。iPhone・iPadの実機確認は後の段階です。

## 旧データ互換性の回帰テスト

既存のGJSがある環境では `python3 tests/test_legacy_storage.py` で実行できます。模擬DOM・localStorageと独立した一時プロセスを使用し、実際のブラウザ保存データやバックアップにはアクセスしません。追加パッケージは不要です。

JSON読み込み時の未保存入力保護は `python3 tests/test_import_unsaved.py` で検証できます（同じくGJSと模擬データを使用）。

作成日時が欠落したメモは、起動時とJSON読み込み時にメモリ上で `createdAt: null`（作成日時不明）へ正規化します。起動時の書き戻しは行いません。空文字や不正日時は拒否します。編集後も作成日時不明を維持します。同日内では作成日時ありを新しい順、その後に不明のメモを元の配列順で表示します。

JSONは `formatVersion: 1` の構造を維持し、`createdAt: null` を許容します。正常な既存バックアップも引き続き読み込めますが、この対応より前の版は作成日時不明のバックアップを拒否するため、復元には対応版を使用してください。同一IDの統合では更新日時、なければ作成日時を比較します。双方に比較可能な日時がある場合だけ新しい側を採用します。同時刻、片方だけ日時がある場合、双方不明の場合はいずれもローカル側を保持します。日時を推測で埋めることはありません。

## 読み込み失敗時の元データ救出

保護状態のエラー表示の下にある「元データを保存」で、保存キーの文字列を加工せず `madalio-recovery-YYYYMMDD-HHMMSS.json`（端末のローカル時刻）へ書き出せます。通常状態では表示しません。救出時もlocalStorageへの書き込みや保護状態の解除は行いません。読み取り不可・保存値なし・ファイル生成失敗は別々に通知します。

救出ファイルは正常なJSONや通常バックアップとしての復元を保証せず、自動修復・復元もしません。保存開始後のキャンセルやディスクへの保存完了はアプリから確認できないため、保存先でファイルを確認してください。

アイコンのみの更新では、アプリ版 `v1.5.0` は維持し、`sw.js` の `ASSET_REVISION`（現在 `icons-2-analytics-1-code-blocks-1`）とアイコンファイル名の `v2`、HTML・Manifest・プリキャッシュの参照を更新します。Manifest参照の `?icons=2` も更新してください。旧キャッシュと分離して新版を準備し、全Madalio画面を閉じた後に適用します。インストール済みアイコンの反映時期はOS・ブラウザにより異なります。

## アクセス解析（Cloudflare Web Analytics）

アクセス状況と表示性能の把握にCloudflare Web Analyticsを利用します。`index.html` の末尾に公式スニペットを配置し、`https://static.cloudflareinsights.com/beacon.min.js` を読み込みます。アクセスしたページや参照元のURL、ページ読み込み時間などのアクセス・性能情報がCloudflareへ送信されます。HTMLをローカルで開いたオンライン環境でもスクリプトの読み込みは行われます。

メモ本文、入力欄の内容、localStorageの保存データを解析へ渡す処理は追加していません。カスタムイベントや独自の追跡も実装しません。通常のメモ処理は解析の読み込みや成功を待ちません。オフラインや通信失敗・ブロック時もメモ機能は利用できますが、その際の計測は保証しません。解析スクリプトと送信先はService Workerのプリキャッシュ対象外です。

このHTML更新ではアプリ版 `v1.5.0` を維持し、キャッシュ識別子だけを `icons-2-analytics-1` へ更新します。従来どおり全Madalio画面を閉じた後に新版へ切り替わり、強制更新はしません。公開後は新版への切り替えとCloudflare管理画面への反映を確認してください。

公式資料：[導入方法](https://developers.cloudflare.com/web-analytics/get-started/)、[収集情報](https://developers.cloudflare.com/speed/observatory/rum-beacon/)。

## コードブロック表示とコピー

行頭のバッククォート3個以上で囲んだ区間だけをコード表示します。開始行の後ろには言語名を付けられます。終了行は開始以上の個数のバッククォートと、必要なら空白・タブだけで記述します。インデント付きフェンス、チルダ、他のMarkdown記法には対応しません。閉じ忘れは開始行以降を通常文字列のまま表示します。コードやHTMLの実行・リンク化・ハイライトは行いません。

ブロック右上でコード本文全体、各行右端でその行だけをコピーできます。全体コピーは元の改行（LF・CRLF）と末尾改行を保持し、行コピーは改行を除いて空白・タブを保持します。空行・空白行に行ボタンは表示せず、空白だけのブロックは全体コピーも無効です。成功時は約800msチェックマークを表示します。長い行は本文だけ横スクロールします。

既存のメモ全文コピーはフェンス・言語指定を含む元本文をコピーします。保存形式・編集・JSON入出力は従来どおりで、解析結果を保存しません。保存時のメモ全体のtrimも維持します。

コードブロック機能を含むアプリ版は `v1.5.1` です。HTMLのCSS・JS参照、JavaScriptとService Workerの版をそろえ、キャッシュ識別子は `1.5.1-icons-2-analytics-1-code-blocks-1` になります。全アプリ画面を閉じた後に更新され、強制リロードは行いません。

コードブロックの解析・DOM・コピー試験は `python3 tests/test_code_blocks.py` で実行できます（GJSと模擬DOM・クリップボードを使用）。
